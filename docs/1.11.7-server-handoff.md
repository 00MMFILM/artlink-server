## 프로필 공개 여부 (2026-09-23~24 추가)

`api/profile-sync.js`:

- `profilePublic`·`visibilityUpdatedAt`을 받는다. `profile` 객체 안과 본문 루트 둘 다 허용한다.
- 공개 OFF는 개인정보를 비운 묘비 행으로 남긴다(`profile_public=false`, `visibility_updated_at` 기록).
- 늦은 요청(서버가 기억하는 시각과 같거나 더 오래된 요청)은 **공개 여부를 바꾸지 못하되 내용은 저장한다**(공개 상태일 때). 비공개 행을 되살리는 요청과 늦은 OFF는 무시하고 `ignored:"stale_visibility"`를 돌려준다.
- `_visibilityOnly` 부분 업데이트 경로를 추가했다. 이 경로는 다른 컬럼을 건드리지 않는다.
- 모든 응답에 서버가 기억하는 `profilePublic`/`visibilityUpdatedAt`을 싣는다. 앱은 이것으로 자기 상태를 맞춘다.
- `isMissingColumnError`가 PGRST204와 "schema cache" 메시지도 인식한다.

`api/artist-browse.js`: `profile_public=false`인 프로필을 목록에서 제외한다. 컬럼이 없으면 필터 없이 다시 조회한다.

## AI 스트림과 배포 순서

기존 `?stream=1` 요청은 `text/plain` 응답을 유지한다. 기존 앱이 NDJSON을 본문으로 받도록 계약을 바꾸지 않았다.

새 앱의 요청은 `?stream=1&protocol=events`이며 응답 형식은 `application/x-ndjson; charset=utf-8`다. 각 JSON 객체는 한 줄로 구분한다.

```json
{"type":"delta","text":"분석 내용"}
{"type":"done","model":"실제로 사용한 모델","promptVersion":"2026-09-17.1"}
```

실패한 스트림은 다음과 같이 끝난다.

```json
{"type":"error","error":"analysis_incomplete"}
```

앱은 `done` 없는 종료와 `error`를 실패로 처리해야 한다. 10자 이상 텍스트가 도착했다는 사실만으로 저장하면 안 된다. `done`의 모델·프롬프트 버전이 최종 메타데이터다.

**서버를 먼저 배포한 뒤 새 앱을 배포해야 한다**는 선행 조건은 **해소됐다.** 2026-09-24 기준 서버 프로덕션 배포가 끝나 `protocol=events`가 운영에서 동작한다. 앱 1.11.7은 이 서버 위에서 배포하면 된다. 기존 plain text 앱의 부분 응답 판별 한계는 새 앱으로 전환해야 해결된다.

## 신규 원본 수집 환경 설정

`ARCHIVE_COLLECTION_ENABLED`가 정확히 문자열 `true`일 때만 동의 헤더를 보관 허용 신호로 처리한다. 환경 변수가 없거나 다른 값이면 신규 사진·음성·영상 학습 원본 보관은 중단된다. 기존 앱이 `X-Data-Consent: 1`을 보내도 기본 상태에서는 보관하지 않는다.

**2026-09-24 기준 이 변수는 설정하지 않았다. 신규 학습 원본 수집은 중단된 상태다.** 소유자와 서버 동의·철회 계약을 정비하기 전에는 활성화하지 않는다. 기존 보관 원본의 철회 경로는 이 플래그와 무관하게 동작한다. 기존 자료를 일괄 삭제하는 변경은 없다.

## 철회 응답의 정확한 범위

로그인된 사용자 본인의 `media-archive` 파일과 `media_assets` 행만 대상이다. 아래 `complete`는 이 범위에 대한 완료이며 전체 계정 삭제나 모든 학습 자료 삭제를 뜻하지 않는다.

```json
{
  "ok": true,
  "complete": true,
  "deleted": 2,
  "scope": "authenticated_media_archive",
  "excludes": ["training_data", "guest_media_archive"]
}
```

- 게스트 또는 인증 확인 불가: HTTP 401, `ok:false`, `complete:false`, `error:"authenticated_archive_only"`.
- 부분 실패 또는 파일 잔존: HTTP 500, `ok:false`, `complete:false`, `error:"withdraw_failed"`, `retryable:true`.
- 파일 삭제 실패 시 메타 행을 지우지 않는다. 파일 삭제 뒤 메타 삭제만 실패했다면 재시도하여 완료할 수 있다.
- 기존 `training_data` 원문과 공통 `anon` 소유자로 보관된 게스트 자료는 이번 API의 삭제 대상이 아니다. 앱 안내도 이 제외 범위를 명확히 해야 한다.
