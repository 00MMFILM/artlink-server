# 분야별 작업실과 학원·극단 공간 — 2026-10-11

현재 상태(2026-10-15 갱신): 운영 Supabase 연결과 앱·서버 검토 브랜치 GitHub 업로드를 완료했습니다. 서버의 Vercel Preview 배포도 성공했습니다. Android ARM64 테스트 APK와 iOS 시뮬레이터 앱의 로컬 빌드가 성공했습니다. 두 앱의 테스트 기기 설치·실행을 확인했고, iOS에서는 주요 화면 이동도 확인했습니다. 운영 웹 배포, 스토어 제출, 일반 이용자 대상 앱 업데이트는 하지 않았습니다.

## 구현한 내용

- 앱 홈의 연기·음악·미술·무용·문학·영화 진입, 분야별 자료와 목표 작성, 한국어·영어 웹 진입 페이지 12개를 연결했습니다.
- 기존 별도 작업에 있던 영어 대사 공부 화면을 현행 앱 코드에 통합했습니다. 10개 장면의 100개 대사 뜻과 20개 표현을 사용합니다.
- 미술은 사진 위 9개 영역 중 확인할 곳을 고르고, 원본을 보관한 채 수정본을 남겨 나란히 비교합니다. AI 분석에는 현재 사진과 이용 가능한 이전 사진을 구분해 전달합니다. 이전 사진이 없으면 시각적 향상을 추정하지 않게 했습니다.
- 커뮤니티에서 학원·극단 비공개 공간으로 들어갑니다. 운영자는 공간 생성, 초대코드 발급, 공지 작성, 구성원 제외를 할 수 있고, 가입 구성원은 단체 대화를 할 수 있습니다.
- 초대코드는 7일 유효하며 재발급하면 이전 코드가 만료됩니다. 제외된 구성원은 읽기·쓰기·코드 재가입이 차단됩니다. 본인 글 또는 운영자 권한의 글 삭제, 신고, 작성자 숨기기를 제공합니다.

- 앱 Jest: 72개 묶음, 1,077개 테스트 통과.
- 실제 PostgreSQL 엔진 기반 PGlite: 접근 분리, 운영자 권한, 초대코드 만료·교체, 익명 접근, 직접 테이블 접근, 재전송 중복 방지 등 27개 검사 통과.
- iOS·Android Hermes 실행 번들 생성 성공. 앱스토어용 네이티브 바이너리 빌드나 실제 기기 검증은 아닙니다.
- 실제 React Native 컴포넌트와 로컬 PostgreSQL 테스트 자료를 이용해 모바일 폭에서 미술 영역 선택·비교, 단체 공지·대화, 계정 변경 후 비공개 내용 제거를 확인했습니다. 실제 사용자에게 테스트 메시지를 보내지 않았습니다.
- 분야 페이지 12개의 메타 정보, 사이트맵, 링크, JavaScript 없는 진입, 모든 목표의 앱 전달, 앱/웹 문구 일치 검사 통과. 한국어·영어 미술 페이지는 브라우저에서도 확인했습니다.

## 운영 DB 연결과 업로드 확인 — 2026-10-14

- 현행 앱과 같은 Supabase `artlink` 프로젝트(`ayvfdomoghppgrleugnk`)에 마이그레이션을 적용했습니다. 새 테이블 4개와 `artlink_group_action` 함수가 존재합니다. **같은 생성 마이그레이션을 다시 실행하지 않습니다.**
- 네 테이블 모두 RLS가 활성화되어 있고, 비로그인·일반 로그인 역할의 직접 조회/쓰기 권한은 없습니다. 로그인 사용자만 권한 검사 함수를 호출합니다.
- 운영 함수 본문 MD5 `6fcf4730077207d3ba905ff64e8cb976`이 검토한 소스와 일치합니다.
- 운영 PostgreSQL에서 임시 UUID와 트랜잭션 안의 인증 정보를 이용해 생성·초대·공지·가입·채팅·재전송·구성원 제외·접근 차단을 검증했습니다. 모든 테스트 자료를 롤백했고 테스트 후 단체 수는 0입니다. 실제 사용자 계정이나 대화는 사용하지 않았습니다.
- 운영 HTTP API에서 비로그인 요청은 HTTP 401 / PostgreSQL 42501로 차단됩니다. 이 검사는 실제 로그인 토큰으로 앱 전체 흐름을 검증한 것과 다릅니다.
- GitHub 검토 브랜치: 두 저장소 모두 `codex/artlink-private-groups-review-2026-10-14`. 앱 기능 커밋 `a1c19ae91457c782e38442e5f628a20a700d5431`, 서버 기능 커밋 `e96ab8abdfd86bcf81511ad11293b80ce4a0467b`의 원격 업로드를 확인했습니다.
- 서버 Preview: https://artlink-server-kmnovtf3r-00mmfilms-projects.vercel.app — Vercel 배포 성공. 보호된 미리보기여서 비인증 요청은 Vercel 로그인 화면으로 이동하며, 이를 기능 검증 성공으로 계산하지 않았습니다.

## 테스트 빌드

- iOS는 기존 `preview` 프로필의 Mac 시뮬레이터용 빌드입니다. Android는 같은 기능 커밋을 별도 폴더에 추출해 Gradle로 만드는 ARM64 테스트 서명 APK입니다. 두 빌드의 업데이트 채널은 `preview`입니다. iPhone용 TestFlight 배포가 아닙니다. Android 테스트 서명 APK는 스토어 서명 앱에 덮어 설치할 수 없으므로 전용 에뮬레이터에서 검증합니다.
- Expo 월간 크레딧 소진 안내가 빌드 요청 중 나타나 클라우드 빌드 두 건을 즉시 취소했습니다. 취소 완료 확인: Android `11f6ba1f-3fd3-47da-a97d-cf534b58f98b`, iOS `f49d2998-b26c-4882-be18-25cb7a7b3996`. 잠시 실행된 부분의 과금 여부는 확인되지 않았습니다.
- 추가 클라우드 빌드는 요청하지 않고 로컬 빌드로 전환했습니다. CocoaPods·fastlane과 Apple Silicon용 OpenJDK 17을 Homebrew로 설치했습니다. Android는 기존 SDK와 NDK를 사용합니다. 운영 Android 서명키를 사용하는 EAS 로컬 빌드는 중단했고, 최종 테스트 APK에는 운영 서명키를 사용하지 않습니다.
- Android 빌드 복사본의 주요 앱 소스와 잠금 파일이 기능 커밋과 일치하고, 설치된 필수 의존성 버전이 잠금 파일과 일치함을 확인했습니다.
- 로컬 iOS 의존성 설치에서 Puppeteer 브라우저 다운로드 오류가 발생해 `PUPPETEER_SKIP_DOWNLOAD=1`로 앱 컴파일에 필요 없는 다운로드만 생략했습니다.
- Expo Doctor는 기존 의존성의 `babel-preset-expo` 버전 불일치(Expo 54 / preset 55), 일부 패치 버전 차이, 프로젝트 내부 EAS CLI 설치를 경고합니다. 빌드 과정에서 자동 일괄 업데이트하지 않았습니다. 공개 전 의존성 정합성을 별도 검토해야 합니다.
- iOS: 1.11.11(94), 시뮬레이터 전용, 로컬 빌드 성공. 전용 iOS 26.5 시뮬레이터에 설치·실행했습니다. 영어 장면 선택 → 한 줄 공부 → 한국어 뜻 → 가리기 → 다음 줄 → 장면 연습 연결을 확인했습니다. 미술 목표의 입력 화면 전달, 단체 공간 비로그인 차단과 로그인 화면 도달도 확인했습니다. 실제 계정 로그인이나 마이크 음질을 검증한 것은 아닙니다.
- Android: 1.11.11(96), ARM64, 테스트 서명 APK 빌드 성공. Java Metaspace 기본 512MiB에서 마지막 검사 중 메모리 부족이 발생해 빌드 명령에만 `-Xmx3072m -XX:MaxMetaspaceSize=1024m`를 적용하고 재시도했습니다. 최종 `assembleRelease`와 필수 린트 검사가 성공했고 APK 서명·패키지·버전 검사를 통과했습니다. 새 전용 Android 15/API 35 에뮬레이터 `CodexArtlink20261015`에 설치·실행했습니다. 버전 96, 프로세스 실행 유지, 앱의 치명적 종료 기록 없음을 확인했습니다. ## 일반 공개 전 남은 순서

1. 아래 실화면 문제 두 건을 고친 뒤 해당 동선을 다시 검증합니다.
2. 소유 테스트 계정의 실제 앱 로그인으로 단체 생성·초대·공지·대화를 끝까지 확인합니다. DB에서 인증 정보를 설정한 트랜잭션 검사만으로 이 단계를 완료 처리하지 않습니다.
3. 운영자 계정 삭제 시 소유 공간이 함께 삭제되는 정책 안내와 운영자 양도 기능을 보강한 뒤 소규모 단체 시험 운영을 진행합니다.
4. 검토 브랜치의 병합, 운영 웹 배포, 스토어 제출 또는 운영 채널 업데이트는 별도 공개 단계입니다. 현재 승인은 GitHub 업로드와 테스트 빌드까지입니다.

## 네이티브 실화면에서 추가로 발견한 수정 사항 — 2026-10-15

- 미술 작업실에서 자료 입력으로 이동하면 분야와 목표는 맞게 전달되지만 상단에 “영상 고르기 / 녹음·오디오 고르기”가 나옵니다. `src/screens/NoteCreateScreen.js`의 `prefill.intent === "material"` 안내를 분야별로 분기해 미술은 사진, 문학은 글·문서가 먼저 나오도록 수정해야 합니다. 현재 사진 첨부는 아래 갤러리 버튼으로 가능합니다.
- 단체 공간의 “로그인하기”를 누르면 회원가입 화면이 먼저 뜹니다. `GroupsScreen.js`가 `setAuthState("auth")`만 호출하고 `AuthScreen.js`가 게스트의 기본 모드를 `signup`으로 정하기 때문입니다. 로그인 의도를 명시적으로 전달하고 로그인 후 단체 공간으로 복귀하도록 보강해야 합니다. 현재도 회원가입 화면 하단 “로그인”을 한 번 더 누르면 기존 계정 로그인 화면에 도달합니다.
- 위 두 문제는 이번 테스트에서 발견했으며, 이 빌드의 기능 소스에는 아직 수정하지 않았습니다.

## 이번 범위의 한계

- 단체 대화는 화면을 보고 있을 때 5초마다 갱신합니다. 푸시 알림, 읽음 표시, 파일·과제 첨부, 이전 대화 전체 탐색은 아직 없습니다. 최근 공지 30개와 대화 100개를 표시합니다.
- 운영자는 최대 3개 공간을 만들 수 있습니다. 운영자 양도·공간 폐쇄 화면은 없습니다. 운영자가 계정을 삭제하면 소유 공간과 관련 기록도 DB 외래 키 정책에 따라 삭제됩니다. 실제 단체 운영 전에 이 정책 안내와 양도 기능을 후속으로 보강해야 합니다.
- 미술 사진은 기존 앱의 기기 내 미디어 저장 방식을 따릅니다. 기기 간 원본 사진 동기화를 새로 구현한 것은 아닙니다. 분석하는 현재 사진은 최대 5장, 이전 버전 참고 사진은 첫 사진 1장입니다.
- 음악·무용·영화는 분야별 시작과 기록 흐름을 연결한 상태입니다. 정밀 음정 분석, 관절 추적, 영화 편집 타임라인 분석까지 완성한 것은 아닙니다.
